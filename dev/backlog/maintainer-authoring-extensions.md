# Extensions beyond the bounded maintainer contract

> **Audience:** Contributors | Integrators
> **Status:** Planned
> **Owner:** Core
> **Last Verified:** 2026-10-28
> **Source Anchors:** `src/Configurator.Core/Definitions/Authoring/`, `docs/internal/MAINTAINER_AUTHORING.md`

These are deliberately excluded extensions, not deferred maintainer-authoring acceptance scenarios.

- **Broader YAML:** Consider additional scalar resolution only when a real target needs it. Acceptance requires an exact JSON-equivalent numeric policy, bounded parsing and explicit rejection of executable/expanding YAML authority; unrestricted deserialization remains unsuitable.
- **Broader JSON Schema translation:** Consider another keyword beyond the delivered v2 profile only for a demonstrated target contract. Acceptance requires proof of equivalent preparation semantics, bounded reference expansion and independent refusal tests. A successful scaffold must never imply full target-validator equivalence. General assertions and reference extensions are tracked in [advanced profile assertions](definition-profile-advanced-assertions.md); do not duplicate that evaluator scope here.
- **Remote authoring/reference retrieval:** Consider only through a separately approved launch/admission contract that binds source content and compiler semantics before answers. Acceptance requires public credential-free bounded inputs, explicit authority, immutable pinning and no answer-bearing requests or implicit package installation.

## Definition v2 graduation boundary

Core v2 admission/evaluation, recursive arrays and fixed/typed maps, nullability,
local acyclic references, bounded conditionals/dependencies, discriminated
variants and importer transformation accounting are delivered behavior, not
remaining maintainer extensions. The
[v2 decision record](../../docs/internal/adr/ADR-definition-standard-v2.md)
preserves the selected contract. Its closed supported importer subset and
refusal of unsupported assertions remain authoritative; no full-schema or
target-validator equivalence follows from scaffolding.

Application versions still use exact declared strings.
[Declared range schemes](definition-profile-version-ranges.md) and
[target/stakeholder trials](definition-profile-target-adoption-trials.md) have
separate owners, triggers and acceptance. Their missing evidence must not defer
selected v2 behavior or become a claim of target acceptance.

For the YAML and remote-retrieval candidates above, Core authoring maintainers
own intake when an actual target triggers the need. Acceptance requires a
separately scoped decision, independent equivalence/refusal/resource vectors,
coherent generated schema and public/internal guidance, and actual affected-owner
qualification. No candidate authorizes dynamic execution, a general evaluator,
v1 compatibility or dependency installation.

Public source-file custody remains with
[CLI public authoring custody](cli-public-authoring-custody.md) and
[directory authority](core-directory-source-boundary.md). Protected output on
[other native hosts](configurator-native-host-evidence.md),
[new formats](configuration-format-expansion.md),
[Event delivery/adoption](guided-configuration-delivery-event.md) and
[publisher distribution](publisher-definition-distribution.md) retain their
independent required work. Schema/profile delivery closes none of those items.
