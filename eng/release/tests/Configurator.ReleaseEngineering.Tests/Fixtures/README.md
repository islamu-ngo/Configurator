## Adaptations and execution boundary

The publication fixture preserves exact-head proposal validation, signed
inventory projection, append-only receipt compare-and-swap, protected mirror
updates, bounded transport retries and observed delivery checks. Its repository,
app ID and paths are synthetic. Publication activation defaults to false.
Configurable launcher syntax is retained solely for adapter-contract validation;
tests override it with a disposable local runtime. No token binding is retained.
Discovery fixture steps are parsed as data and are never installed as workflows.

Native C# file-based validators execute only when the tests explicitly invoke
them. They are excluded from the test assembly's compile glob, and their helper
types have Configurator namespaces instead of inherited warning suppressions.
The bundler invokes the colocated checksum fixture, not an active CI script.
Provider fixtures retain the generic `no-checkout-discovery` contract.
The disposable publication repository uses `main` consistently for inventory
publication and race injection, while retaining a synthetic `develop` branch for
the independent failed-fetch regression. Provider links use a synthetic repository.
Impact classification retains historical path examples as test data only;
those examples neither load Event source nor grant publication authority.

The provider fixture uses the existing centrally versioned YamlDotNet dependency;
no third-party implementation source was transferred. Synthetic authorities are
generated by tests inside temporary directories and restored after each scope.

`Trust/allowed-signers` and `Trust/promotion-allowed-signers` are test-authored
comment-only files. `Trust/release-signing-policy.yaml` is a test-authored inactive
policy. They provide the omitted inactive-data contract without copying any
Event signer or activation authority. Packaged-default tests explicitly load
these inert defaults before checking fail-closed behavior.
