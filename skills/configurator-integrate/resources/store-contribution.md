# Prepare an optional store contribution

First check/build the source independently with the standalone CLI. The store uses the same source and compiler; it cannot be a prerequisite for local CLI, native or browser use.

Place one source in the selected project directory. Include credential-free public repository information and an explicit license for the definition itself; the application's license is not an inferred redistribution license. Optional curator metadata supplies only tags or a meaningful slug exception. Do not recreate handwritten expanded project/runtime inventories.

Retain all canonical historical releases unchanged. New content uses a new revision. Store validation compares history against a separately supplied pinned target baseline; a contributor cannot select its own authority, remove admitted history or rebind a family to a different project.

Run the store's native self-test and write/check commands in the store repository's documented lane. Review public text and default suitability manually: schema admission does not certify content or publisher trust. Return a review draft with source, generated release/digest and exact validation evidence. Do not publish a PR or claim curation/signing authority.
