# Scaffold from a public schema

Use `definition init --from-schema` with a local public Draft 2020-12 schema. Supply only explicitly selected, root-confined local reference documents through the installed command's declared interface. No remote reference fetching is allowed.

Import scaffolds the bounded-v2 profile, not a general JSON Schema evaluator. Supported shapes include explicit scalar types, nullable scalars, homogeneous typed scalar enums, recursive constrained array items, closed objects, typed maps, closed discriminator branches and corresponding numeric, length, cardinality and uniqueness assertions. Untyped `additionalProperties: true`, tuples, general unions/composition, regex and unsupported assertions reject rather than disappear. Do not infer support for arbitrary conditional schemas from bounded runtime relationships.

Supplied local reference expansion is offline, bounded and acyclic; remote/dynamic references and resource rescoping reject. Source local references remain confined to the configuration root. A standalone null schema becomes a nullable scalar restricted to enum `[null]`, with a conversion record.

Defaults/examples are discarded and reported, never copied into `initialValue` or `suggestedValue`. Collected leaves remain sensitive; `writeOnly` ancestry remains secret through nested shapes and references. Structural containers and supplied public constants are explicitly classified public with conversion records; protected descendants still raise effective sensitivity. Absence of `writeOnly` never proves public classification. `format`, `readOnly` and `deprecated` remain advisory annotations, not validators, initialization or permissions.

Review the immutable `Transformations` ledger on both result and refusal. Classifications are retained, converted, advisory, discarded and unsupported; each entry has a stable code, bounded public schema pointer and document ordinal, never a filesystem path or raw scalar. Report encountered conversions/discards and unresolved assertions, not obsolete difference strings.

`--accept-bounded-semantics` acknowledges encountered numeric-domain and nullable-provider conversions only. Int64/exact-decimal bounds are not arbitrary JSON numeric precision; nullable variants admit null outside branch selection, unlike an object-only JSON Schema `oneOf`. Acknowledgment cannot bypass unsupported assertions, privacy rules or invalid output behavior. Requiredness is presence and string length counts Unicode scalars; do not repeat retired nonblank/UTF-16 difference claims.

Review generated configuration, exact target versions, output selection and inherited privacy before check/lint/build. Include one supported and one refused synthetic schema, then complete and incomplete synthetic answer flows with independent target expectations. Keep schema discovery structural and built-in; successful scaffolding/admission never implies target-validator equivalence, adapter qualification or authority to apply.
