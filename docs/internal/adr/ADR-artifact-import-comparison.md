# ADR: Evidence-Aware Configuration Assessment

> **Status:** Accepted design; implementation and qualification in progress
> **Date:** 2026-10-30
> **Owners:** Core and Presentation

## Context

Operators already possess ordinary JSON, YAML or dotenv exports. They need to
reuse represented values or determine what a selected newer definition requires.
A private answer snapshot would simplify reconstruction but would not satisfy
this workflow. A plain file also lacks historical definition and release
provenance: textual differences cannot establish renamed fields or target safety.

The existing strict inverse and shared validator supply the relevant authorities.
Normal validation applies initialization, which must not conceal absence during
assessment. Interactive clients also contain current answers and uncommitted
drafts that a comparison must not change.

## Decision

Extend the existing projection inverse within a proved bounded algebra. Preserve
observed value, observed absence, unobserved and public context-derived evidence.
Thread this evidence into the sole validation kernel with initialization disabled
for assessment. Do not introduce another evaluator, inverse definition language
or compatibility translator.

Separate the disposable private recovered-evidence owner from immutable,
value-free report facts. Separate file coordinates, declared schema locations
and current-workspace correction tokens. Imported row/map ordinals never select
current entities. Comparison and explanation navigation preserve drafts,
answers, provenance, omissions, revision and prepared output.

Presentation owns one current interactive proposal under its existing mutation
and privacy gate. All raw imports require the applicable custody authority,
including unknown credentials under a public-only schema. Revocation denies
access before cleanup and generation fences prevent stale publication.

Make Compare the default. Deliberate Fill fields rechecks eligibility, consent
and current conflicts and adopts all recovered admissible values atomically.
It may replace untouched initialization but not explicit answers, omissions or
drafts. Structural or unknown input cannot produce best-effort partial adoption.

Expose execution, compatibility, coverage, inventory and adoption eligibility as
independent facts. Keep preparation and target acceptance separate. Retained
findings remain fully pageable; resource stops never become compatibility.

## Alternatives

- Requiring a Configurator answer envelope loses the ordinary-export workflow.
- Framework configuration binding changes exact key and presence semantics.
- A second schema evaluator duplicates the consequential conditional rules.
- General migration metadata or guessed renames introduces authority absent
  from the file and duplicates the export definition.
- Reusing workspace correction tokens can target unrelated current rows or maps.
- Partial adoption hides rejected content and destroys atomic conflict handling.

## Consequences

The supported inverse is deliberately narrower than export expressiveness.
Unsupported or incomplete assessments are visible outcomes. Requiredness follows
proved evidence, not an invented complete answer tree. Operators may need to
repair a separate copy before autofill becomes eligible.

This requires independent literal and actual Event inverse tests, composed
privacy/draft/stale-operation tests, complete machine paging checks and actual
client qualification. No design decision alone proves responsiveness,
accessibility, enterprise support or another host's behavior.

Managed private-tree retirement is not physical string erasure. Native output
retains its existing protected create-only contract; Browser export remains
deliberate local copy/download. Preparation confers no target apply authority.
