### IVSD-F001: Preserving Explicit Custody Truthfulness, Fail-Closed Inherited Secret Badges & Safe Dirty-Document Close Fencing

First-time self-hosters and security-conscious administrators depend on the browser workspace to communicate truthfully which settings are secrets, when secret entry is locked, and whether unapplied private edits are safely resolved before closing a tool panel. Source inspection exposed two severe provider-controlled risks alongside the audited chrome defects: (1) `ConfigurationInspector.razor` checks only local JSON `x-configurator.sensitivity`, so adding a human-first `[👁] Standard` vs `[🔒] Secret` badge without passing authoritative inherited `DefinitionSensitivity` would falsely label nested child fields inside a `secret` parent object as `"Standard (not a secret)"`; and (2) promoting a unified `×` close button into `DockPanelHost` without routing BOTH `DockSideHost` and `DockOverlayHost` through `WorkspaceUtilityDockCoordinator` -> `ResolvePendingAsync()` would allow closing a dirty `Document (JSON)` panel without resolving pending edits or cleanly retiring its CodeMirror JS lease, while deleting `#profile-vault-heading` / `_developerPanel.Heading` would break keyboard focus on opening `Profiles` and `Document (JSON)`.

Provider responsibility (`Amanah` — trustworthy stewardship of sensitive inputs and edits; `Sidq` — truthful, unambiguous security signaling) requires fail-closed design across every custody seam: (a) `ConfigurationFieldMetadataView` MUST derive `[🔒] Secret` vs `[👁] Standard` exclusively from authoritative `DefinitionSensitivity` (`DefinitionSensitivityPolicy` / `IsSecret` / `state.Sensitivity`), failing closed so nested or unresolved secret fields NEVER display `Standard`, and live secret values NEVER enter `?` Help, docked `Inspector`, tooltips, or expanded `<details data-technical-details>` (guarded by Red-Phase `TASK-4.1` "Worst Break" #1); (b) `DockPanelHost` MUST route unified `[data-action="close-dock-panel"]` clicks in both docked and overlay modes through `CloseWorkspaceUtilityAsync()` -> `ResolvePendingAsync()` and expose unified `DockElementIds.PanelHeadingId(id)` focus targets (guarded by Red-Phase `TASK-3.1` "Worst Break" #2); (c) `base.css:22-25` MUST stop stretching raw checkboxes to `44×44px` so `#secret-consent` (strictly unchecked by default inside its Tier 2 consent card) and `Profiles` checkboxes render cleanly inside `>= 44×44px` label hit targets; and (d) `WorkspaceHeader` MUST retain `[data-workspace-consent-chip]` and 1-click `[data-action="revoke-secret-entry"]` outside disclosures whenever unlocked, keeping idle `[data-status-slot="reserved"]` `.sr-only` (`CLS = 0`) while preserving every core custody disclosure across `Import`, `Profiles`, and `Trust & Privacy`.

- **Principle, domain & stakeholder:** `Amanah` (Stewardship) & `Sidq` (Truthfulness) / security, privacy & UX; affects self-hosting administrators and privacy-sensitive operators.
- **Provider-controlled decision:** Sensitivity badge authority, unified drawer close/focus lifecycle, consent-control rendering, and custody disclosure wording.
- **Evidence & validation level:** Live Chrome DevTools MCP inspection (`audit-light-trust-privacy.jpg`, `audit-dark-desktop-import.jpg`) + CTO source verification of `ConfigurationInspector.razor:59-62`, `ConfigurationFieldHelp.razor:42-115`, `DockOverlayHost.razor:25`, `DockSideHost.razor`, `ConfigurationEditor.razor.cs:1195-1198`, `base.css:22-25` (source traceability, not runtime proof).
- **Linked mitigation:** `IVSD-M001`.
- **Owner / next validation:** Phase 1 (`TASK-1.3`), Phase 2 (`TASK-2.4`), Phase 3 (`TASK-3.1`, `TASK-3.4`), Phase 4 (`TASK-4.1`, `TASK-4.4`), Phase 5 (`TASK-5.5`) bUnit custody & dirty-close suites + Published-Browser `Q04-secret-consent-and-hosted-custody` & `Q11-custody-sink-canary-checks` (`POST-1`).

### IVSD-F002: Non-Color Multi-Step Progress Encoding, Single-Authority Breakpoints, Full AA/AAA Contrast & Systemic Accessible Controls

Operators with color-vision deficiency, low vision, motor impairments, or narrow tablet/phone viewports (`900×900`, `500×844`) are currently excluded by wrapped 10–14-row section button walls pushing the first field `1,068px–1,389px` down, collapsed Light/Dark surface tiers, transparent inputs, and two source-verified gaps caught during CTO review: (1) `AbyssalDark.LightPalette.TextSecondary` (`#71717A` on `#F5F5F7` = `4.41:1`), `PureWhite.LightPalette.TextSecondary` (`#71717A` on `#F6F7F9` = `4.45:1`), and `ThemePaletteGenerator.GenerateLightPalette` (`textSecondary` never calling `EnsureContrast(..., 4.5)`) fail WCAG AA text contrast; and (2) `MainLayout` (`DockScope.Shell`) and `ConfigurationEditor` (`DockScope.Workspace`) both mount `DockLayoutHost` and write to a single `DockLayoutState._isMobileViewport` boolean, meaning splitting breakpoints inside `DockLayoutHost` would trigger nondeterministic dock/overlay thrashing at `761–1024px`.

### IVSD-F004: `ThemePreference`-Direct Bounded Storage, OS-Switch Preference Persistence, Dynamic `>= 420px` Floor & Zero-Friction User-Initiated Tour Autonomy

Two cross-cutting design choices govern storage boundaries, layout protection, and visitor autonomy: (1) switching the desktop utility rail from cryptic `44px` icons to stacked icons + visible concise labels (`80px`: `Inspect`, `JSON`, `Import`, `Profiles`, `Privacy`) with a global `Toolbar labels` setting (`Show labels` | `Icons only`), and (2) deleting `[data-onboarding-cue]` while offering an optional `"Quick tour"`.
