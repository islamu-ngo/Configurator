### IVSD-F001 - Private storage must remain owned until its physical consumer settles

Closing or cancelling an interface can retire its visible workspace before an external operation finishes consuming memory. Clearing that memory too early can make a consumer observe different bytes; abandoning it too late can retain private information unnecessarily. The provider controls the storage lifetime, cancellation protocol and close behavior.

Desktop currently clears active save/import storage during disposal without awaiting physical settlement. Browser output retirement also crosses asynchronous interop boundaries. Both require an explicit distinction between immediate denial of UI access and the physical owner's final cleanup. Trust (Amanah) and non-harm require both boundaries to be deliberate.

- Lifecycle / severity / claim type: open / high / source-derived ownership risk.
- Domains / stakeholders: technical, design, operations / operators and people represented in configuration.
- Controlled decision: who owns each buffer before execution, during consumption, after invalidation and after close.
- Evidence / validation level: E01, E04, E08 / source traceability; no new runtime reproduction.
- IVSD-M001: operation-owned native buffers; immediate capability invalidation; settlement-owned clearing; bounded graceful close with an explicit unknown outcome rather than fictional cancellation; safe Browser export retirement.
- Owner / next validation: Desktop, Artifacts and Browser maintainers; controlled dispose-before-consumption and delayed-interop regressions.
- Escalation: forced process termination cannot promise managed erasure; any changed retention, worker messaging or persistence boundary requires renewed review.

### IVSD-F002 - Historical publication facts must survive editable-state changes

An operator who is told only that a save was cancelled may repeat the action even though the first file was installed. An installed-but-unverified file also requires different recovery from a refusal before installation. The provider controls whether this distinction remains available after editing, cancellation or an observer failure.

The shared native writer already preserves installation, verification and cleanup facts. Terminal retains bounded receipts independently of readiness. Desktop currently gates feedback on whether the originating operation remains current. Truthfulness (Sidq) requires historical facts to survive without restoring stale answers or enabling another save.

- Lifecycle / severity / claim type: open / high / source-derived feedback gap.
- Domains / stakeholders: design, technical, operations / operators and automation consumers.
- Controlled decision: receipt retention, unknown/unattempted distinction and recovery instructions.
- Evidence / validation level: E01, E02 / source traceability and existing test inspection.
- IVSD-M002: bounded value-free receipts for at most one active attempt and the newest 16 settled attempts, each defensively snapshotting at most 64 outcomes; independent installation, verification, cleanup and completion facts; no automatic retry or bundle rollback claim.
- Owner / next validation: native client and Artifacts maintainers; cancellation after installation and partial-prefix scenarios.
- Escalation: changing create-only publication or claiming continued destination integrity requires a separate authority review.

### IVSD-F003 - People must be able to express and repair the same answer in each client

Absence, an empty container, an invalid unfinished draft and an accepted value are different user intentions. Desktop's local structured reconstruction can blur leaf errors, and its controls do not expose all empty-container actions. Terminal refresh can replace the visible rejected draft with committed content. These differences impose avoidable correction work on users based on their selected client.

Justice (Adl), rights of people and excellence (Ihsan) support one editing meaning with native interaction. This does not require identical controls. The shared path-based editor already offers the relevant semantic seam.

- Lifecycle / severity / claim type: open / medium / source-derived editing and accessibility gaps.
- Domains / stakeholders: design, technical, evaluation / graphical, terminal, keyboard and Arabic-language users.
- Controlled decision: presence, draft preservation, error attribution, focus and translated control actions.
- Evidence / validation level: E03, E05 / inspected controls and shared contracts.
- IVSD-M003: route Desktop mutations through shared literal-path editing; expose deliberate container presence; restore Terminal drafts through custody-fenced reads. Phase 4 owns neutral/Arabic Desktop action resources and exact-culture rendered-copy checks without parent fallback; broader Terminal locale/AT work retains its separate required gate.
- Owner / next validation: Presentation and client maintainers; independent semantic vectors and real control actions.
- Escalation: headless tests do not certify assistive technology, bidi shaping or terminal cell widths; those claims retain actual-surface gates.

### IVSD-F004 - Browser custody must be mandatory and bound to the current registration

A missing policy service currently permits a successful editor start, while ordinary fixtures omit the production policy. Navigation also identifies an owner object after asynchronous cleanup rather than retaining the exact registration. A replacement registration by the same component can therefore be confused with the discarded registration.

The provider controls dependency wiring, registration leases and public-source eligibility. Avoiding spying (Tajassus), trust and promise-keeping require the browser's local-only boundary to remain active across startup, navigation and connection changes.

- Lifecycle / severity / claim type: open / high / structural fail-open risk and source-derived lifecycle race.
- Domains / stakeholders: technical, design, governance / browser operators and hosted-browser users.
- Controlled decision: mandatory preparation, registration release, connectivity state and active-workspace source denial.
- Evidence / validation level: E04 / source traceability; no observed disclosure.
- IVSD-M004: required policy injection; production-equivalent fixture setup; exact registration leases through discard; current connection signals that never override active-custody denial.
- Owner / next validation: Browser maintainers; held-cleanup same-owner registration, failed worker acknowledgment and reconnect scenarios.
- Escalation: no answer-bearing network, public cache, storage or application-worker message is admitted.

### IVSD-F005 - Efficiency improvements must preserve one semantic authority and honest readiness

Preparing outputs twice creates unnecessary private copies and work. However, removing aggregate admission or calling synchronous composition "responsive" would trade visible speed for misleading guarantees. Operators need exact outputs and truthful complete/draft/withheld status.

The provider controls semantic evaluation, ownership transfer and the claims attached to an optimization. Excellence and truthfulness support eliminating duplicate work without a second evaluator, scheduler framework or weakened budgets.

- Lifecycle / severity / claim type: open / medium / verified duplicate work and unmeasured performance risk.
- Domains / stakeholders: technical, design, evaluation / low-resource and offline users; maintainers.
- Controlled decision: bundle admission, prepared-output adoption, cancellation and performance claims.
- Evidence / validation level: E06, E09 / source traceability and inherited backlog constraints.
- IVSD-M005: compose each selected output once; safely adopt the already prepared result; reuse authoritative validation internally; preserve draft withholding, aggregate limits and output retirement. Keep full Browser preparation responsiveness in its named required follow-up until measured and implemented.
- Owner / next validation: Core, Presentation and Browser maintainers; independent format vectors, aggregate-failure and never-started adoption tests.
- Escalation: answer-bearing worker execution, asynchronous erasure or relaxed output/latency budgets is not an available shortcut.

### IVSD-F007 - Public revision tooling must not silently replace another person's edit

The current public-source revision protocol documents its cooperative-writer limitation. A noncooperating editor can change the source after comparison and before replacement. The provider can reduce that particular harm by producing a separate create-only revision candidate for explicit human review.

Rights of people, trust and non-harm apply to the maintainer's authored source and comments. This is public authoring, not permission to treat private configuration as public or to weaken restricted writes.

- Lifecycle / severity / claim type: open / medium / documented concurrency limitation.
- Domains / stakeholders: technical, design, governance / definition maintainers.
- Controlled decision: in-place replacement versus explicit candidate creation and honest authority claims.
- Evidence / validation level: E11 / current source and backlog inspection.
- IVSD-M007: require an explicit non-source output for changed revision candidates, create-only publication and preserved source bytes. Require an invocation-supplied CLI authoring capability for discovery, anchor/existence checks, source/fork/environment/schema reads and staged writes; migrate the composition root and all constructor callers with no ambient native fallback. Keep captured-handle/root-exclusion guarantees in the separately owned native-authority follow-up until actually implemented.
- Owner / next validation: CLI and Artifacts maintainers; concurrent editor-save, alias, existing-output and overflow vectors.
- Escalation: candidate-only behavior does not itself prove captured filesystem identity or qualify new hosts.

## Recommendations

Implement the responsibility corrections in small independently reviewable slices. Reuse existing Core, Presentation and Artifacts owners; keep UI dispatch and controls in each client. Permit clean contract replacement, as the user requested, without compatibility aliases.

Rejected alternatives are clearing active buffers to make close appear complete, discarding stale installation facts, one error flag for a structured root, optional custody wiring, removing aggregate preparation checks, broad shared-service frameworks, and treating counts or mocks as qualification.

Amanah applies to each entrusted private buffer and source file. Sidq applies to installed/prepared/draft/unknown and qualification claims. Adl applies to equivalent meaning across clients and accessible correction. Non-harm applies to disclosure, lost drafts and destructive races. Rights of people apply to consent and authored source. Ihsan applies to maintainable shared behavior and relevant testing. Tajassus excludes telemetry or answer-bearing offloading as performance shortcuts.

The strategic domain preserves a small offline utility. Design covers correction, receipts and deliberate export. Technical covers shared authority and generations. Operations covers actual-host evidence and close limits. Governance covers release truthfulness and scope ownership. Evaluation covers independently specified behavior and retained measurements.

## Common Overlooked Failures And Outcomes

- A cancelled UI can coexist with an installed file.
- Unknown is not equivalent to certainly unattempted.
- A changed registration can belong to the same component object.
- Empty and absent containers are different answers.
- Private drafts can survive in shared state while disappearing from a control.
- Clearing output synchronously and reclaiming interop metadata are separate obligations.
- A candidate file avoids source overwrite without proving descriptor-bound authority.
- A faster synchronous operation is not proof of a responsive Browser event loop.
