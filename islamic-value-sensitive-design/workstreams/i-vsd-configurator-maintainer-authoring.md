## Findings

### IVSD-F001 — Convenience must not collect or disclose private values

An integration agent can be tempted to read `.env`, real answer files or credential stores to infer types and examples. That makes the maintainer's private operating data part of the integration process and can expose values through a generated public definition, PR, model context or diagnostic. Public-looking parent objects can also hide secret defaults. A faster authoring experience cannot make that collection necessary.

The provider controls discovery inputs, compiler defaults and diagnostics. Use source declarations, public schemas, key-only `.env.example` inspection and synthetic fixtures. Omitted sensitivity stays conservative; `writeOnly` raises the floor, while absence of that annotation never proves publicity. Compile through existing recursive privacy/default admission and preserve restricted answer output, browser workspace consent and clearing. These controls connect **Amanah** to stewardship of entrusted credentials and **avoiding Tajassus** to avoiding unnecessary collection. They also address **non-harm** from accidental repository disclosure.

**IVSD-M001:** restrict discovery; never copy example values automatically; require reviewed public defaults; prove nested-default and diagnostic-sentinel rejection; retain browser secret consent/revocation and native protected output. This costs a meaningful human classification decision and deliberately avoids claiming perfect secret inference. File/schema metadata can itself include inappropriate personal content; admission is not a certification of public suitability.

### IVSD-F002 — Generated identity and store labels must not become authority

Tooling can remove GUID homework without making a generated GUID or repository label authenticate a maintainer. A changed source under the same revision, or removal of old snapshots in a contribution, can otherwise replace previously trusted configuration silently. Event's outputs include consequential identity/legal artifacts; preparing their bytes must not imply that Event accepts or authorizes them.

The provider controls family allocation, immutable canonical revision comparison, retained history, discovery labels and target-authority claims. Persist identity once, compare new content against trusted prior public snapshots, and keep receivers' conflict history. Store CI obtains its baseline from a pinned target commit outside contributor control. Event validates target payloads in Event; the generic compiler gains no credentials or execution permission. **Truthfulness** applies to the distinction between an integrity identifier and authenticated publisher identity; **Amanah** applies to preserving an admitted contract rather than silently changing it.

**IVSD-M002:** machine-managed lineage, explicit revisions/forks, baseline-backed history checks, unverified display labels and explicit preparation-versus-acceptance guidance. Event's generated public compiler/source/output facts are descriptive reproduction provenance; they cannot activate signing, promotion or publisher trust. The baseline is a curation integrity control, not cryptographic publisher authentication. A party controlling the whole repository can rewrite its public inventory; this design does not claim to solve that authority problem.

### IVSD-F003 — Adoption must remain independent and equally capable in both formats

A maintainer who cannot use the store should still be able to ship a definition with their software. If handwritten YAML has fewer capabilities, requires synchronized JSON, or is silently converted by an agent, the promised easy integration instead creates a second maintenance burden. CLI-only support would also leave Browser/Desktop/Terminal users with different semantics.

The provider controls syntax normalization, discovery, compiler ownership, distribution and accessibility. One source and shared compiler make both formats equivalent; competing automatic sources reject instead of introducing hidden precedence. Local client adapters use the same admitted definition; a maintainer publishes canonical JSON independently. The store remains optional. **Justice** concerns fair access across workflows and **promise-keeping** concerns credible portability. **Ihsan** concerns reliable, maintainable behavior and accessible existing loader semantics.

**IVSD-M003:** YAML-default scaffolding, equal JSON support, exact byte/digest equivalence, source-format/comment preservation, store-free packages and a portable skill with no repository-specific runtime dependency. YAML remains an explicitly restricted dialect; unsupported syntax is an actionable limit rather than a false compatibility promise. The plan cannot prove that the remaining explicit privacy/version decisions are easy enough for real maintainers.

### IVSD-F004 — Import and AI assistance must describe their actual limits

JSON Schema `required` does not mean nonblank text, numeric domains differ, annotations are not always assertions, and a default is not evidence that a value is safe to publish. An importer that silently changes those meanings can give an operator false confidence. An agent can similarly describe files as validated merely because it generated plausible declarations. A secret-deferred draft is another case where a polished result can conceal incomplete readiness.

The provider controls supported import semantics, machine status, evidence reporting and target claims. The plan translates a closed subset, refuses unsupported assertions, enumerates known bounded differences and makes acknowledgment explicit. Existing Core readiness remains authoritative; Event's target codecs remain its acceptance authority. The skill reports commands actually executed and facts still requiring maintainer review. **Sidq** applies to accurate validation/readiness claims and **avoiding Gharar** to removing uncertainty about what import/AI/preparation actually guarantees.

**IVSD-M004:** documented import subset, strict default refusal, bounded-difference acknowledgment that cannot bypass unsupported/privacy rules, actual machine evidence, truthful draft labels and no target/legal/agent correctness certification. Source-only Event CI must not claim compiler conformance; the positively selected compiler lane fails when its independently provided package/pin is absent or invalid. This means some schemas need direct authoring or a target-owned exporter. That is a clearer burden than hidden semantic weakening.

### IVSD-F005 — Public integration material needs its own rights/provenance review

The application being open source does not establish the license of every schema, image, copied description, generated example or third-party implementation used in an integration. Likewise Event's first-party MIT transfer authority does not relicense arbitrary external expression. Automatically copying metadata into a store PR could create an unsupported redistribution promise.

The provider controls what is copied, the source contract's license declaration, store review and packaged notices. Use source-free functional research, explicit definition-material licensing and existing provenance/notices. The generated field/output structure is independently designed around repository contracts. A license declaration is a contributor claim to review, not legal verification by the compiler. **Rights of people** includes intellectual-property interests; **Amanah** and **promise-keeping** apply to the terms users receive.

**IVSD-M005:** explicit reviewed definition license for redistribution, bounded optional curation, first-party transfer documentation, preservation of dependency identity/notices and a skill that drafts a rights/evidence-aware contribution without publishing it. No new third-party implementation or dependency is justified here. Future material imports are evaluated individually.

## Recommendations

Accept IVSD-M001–M005 as implementation obligations. Keep meaningful privacy/target facts explicit and generate repetitive metadata. Prefer one shared compiler and ordinary existing native tools; keep independent distribution and store compilation the same contract. Reject AI-only validation, store-only availability, silent schema weakening and automatic collection of real settings. Reject unrestricted YAML expansion and remote authoring as initial shortcuts: their added authority/precedence is unnecessary for the requested experience.

Technical alternatives and sequencing live in the implementation plan. No new religious ruling or certification is recommended. No payment/financing decision occurs here, so riba-related analysis is not applicable to this feature.

## Stakeholders

Maintainers own accurate target facts and reviewed privacy classifications. Operators own deliberate answer/export actions; they must see truthful readiness. Store reviewers own curation/provenance and immutable inventory checks. Event owners retain target semantics/authorization. Upstream rights holders retain their terms. Users with different source-format preferences or assistive technologies need equal supported capability. Agents accelerate the workflow; they are not an authority over any stakeholder's credentials, rights or acceptance.

## I-VSD Principles And Domains

Trust, truthfulness, rights of people, non-harm, avoiding spying/deception/uncertainty, justice, promise-keeping and excellence are applied to the concrete controlled choices above. Strategic review concerns independent adoption; design concerns safe defaults/claims; technical review concerns admission/custody/history; governance concerns authority/provenance; operational review concerns actual packages and support claims; evaluation concerns real evidence and stakeholder outcomes. These applications do not imply an Islamic certification of the implementation.

## Common Overlooked Failures And Outcomes

Quoted-looking YAML numbers can become strings, while unquoted keys can lose their type; paired syntax tests must check both. Human help text changes identity when included in runtime, while comments do not. Comment-preserving source edits must distinguish UTF-8 offsets from decoded character offsets and document the external-editor race limit. Removing a store source cannot remove a trusted prior revision. Local authoring must not bring native includes/schema fetch into Browser. A declared license, GUID, store badge or successful draft cannot substitute for reviewed rights, publisher authentication, readiness or target authorization.
