### IVSD-F006 / IVSD-M006 — Preserve installation without promising continued integrity

The provider controls the writer result and every client receipt. Successful namespace publication establishes installation even if the following identity/permission inspection fails. Reporting only `TargetChanged` can conceal an already installed file and encourage an unsafe retry. Active A2–A6 must establish the fact at publication, retain failed/unverified inspection separately, stop the next bundle member and preserve the fact through cleanup/cancellation/receipt faults. Receipts remain value/path-safe. Existing-target and unsupported-host refusals remain fail-closed.

This is an open, high-severity truthfulness/custody obligation grounded in Sidq, Amanah and Non-harm, affecting operators and people represented in output. Source evidence is inherited plus refreshed at the named revision; dynamic verification remains required. Artifacts and the three native client owners own next validation. Broader output/draft semantics, Desktop physical settlement and host confidentiality remain deferred as listed below. No rollback fiction, native ordinary-file fallback, Browser equivalence or continued-integrity guarantee is accepted.
